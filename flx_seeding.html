Seeding and Reading

The algebra of Hyperdual Algebra returns every derivative of an evaluation at once. Which argument each of them differentiates is decided when the arguments are seeded.

Assigning units to arguments

Seeding a value is adding units to it. The argument a unit is given to is written in the call, and two forms write it. flx::variable<Ord> gives every unit of the order to a single value, and flx::variables<Is...> spreads the units of a call over its arguments:

auto x = flx::variable<2>(2.5);
auto [ u, v ] = flx::variables<0, 1>(2.5, -1.0);
auto [ p, q ] = flx::variables<0, 0, 1>(2.5, -1.0);

The template list Is... holds one entry per unit, in unit order: its \(i\)-th entry is the index of the argument \(\varepsilon_i\) is given to, arguments being counted from zero and units from one. Its length is the order every seeded result comes back at. The third call above gives units 1 and 2 to the first argument and unit 3 to the second, hence an order 3 on both.

An argument that is given no unit comes back unchanged, at its own type, so the result of a call to flx::variables feeds the function straight through kumi::apply.

Taylor identity

Substituting a nilpotent into an analytic function turns its series into a sum with finitely many terms, since every monomial of degree \(n+1\) in the units vanishes. That truncation is an identity, and no approximation.

For a function \(f\) of \(m\) arguments, seed argument \(j\) with the units of a set \(U_j\), the sets \(U_1, \dots, U_m\) partitioning \(\{1,\dots,n\}\):

\[ x_j = a_j + \sum_{i \in U_j} \varepsilon_i. \]

Each unit then belongs to exactly one argument, and \(k\) denotes the map reading that assignment back, \(k(i) = j\) for the single \(j\) with \(i \in U_j\). It is the list Is... of the previous section. The evaluation gives

\[ f(x_1,\dots,x_m) = \sum_{S \subseteq \{1,\dots,n\}} \left(\frac{\partial^{|S|} f}{\prod_{i \in S} \partial x_{k(i)}}(a_1,\dots,a_m)\right) \varepsilon_S. \]

Every component of the result is a partial derivative of \(f\) at the point, and it carries no factorial: each unit appears to the first power, so the coefficient of \(\varepsilon_S\) is the derivative itself.

Reading a result

A component is indexed by the units it carries, as Component indexing states. With the seeding flx::variables<0, 1>(x, y) and \(f\) evaluated on the pair, the four components hold

Component Units What it holds
get<0> none \(f(x, y)\)
get<1> \(\varepsilon_1\) \(\partial f/\partial x\)
get<2> \(\varepsilon_2\) \(\partial f/\partial y\)
get<3> \(\varepsilon_1\varepsilon_2\) \(\partial^2 f/\partial x\,\partial y\)

One evaluation returns the gradient and the mixed second derivative. Absent from it is \(\partial^2 f/\partial x^2\): a second derivative in one argument needs two units on that argument, which flx::variables<0, 0> asks for.

Two units per argument gives the square terms as well. Seeding two arguments that way costs order 4 and returns, in a single evaluation, the value, both first derivatives and the whole Hessian:

auto [ x, y ] = flx::variables<0, 0, 1, 1>(2.5, -1.0);
Component Units What it holds
get<1> \(\varepsilon_1\) \(\partial f/\partial x\)
get<3> \(\varepsilon_1\varepsilon_2\) \(\partial^2 f/\partial x^2\)
get<5> \(\varepsilon_1\varepsilon_3\) \(\partial^2 f/\partial x\,\partial y\)
get<12> \(\varepsilon_3\varepsilon_4\) \(\partial^2 f/\partial y^2\)

Several components hold the same derivative, \(\varepsilon_2\varepsilon_3\) answering \(\partial^2 f/\partial x\,\partial y\) as \(\varepsilon_1\varepsilon_3\) does. A symmetric object stored as a full set of subsets repeats itself, and that repetition is what caps the useful order at four.

Cost of an order

An order \(n\) carries \(2^n\) components, so a single value of order 4 weighs sixteen double, and every operation of the arithmetic works on all of them. Two ways of spending that budget answer different questions.

  • One unit per argument. Order \(m\) over \(m\) arguments returns the gradient and every mixed partial up to the one of order \(m\), in one evaluation, and never a repeated derivative.
  • Several units per argument. Order \(n\) over one argument returns \(f', f'', \dots, f^{(n)}\) of that argument in one evaluation, and says nothing of the others.

A full Hessian of \(m\) arguments therefore comes out of one pass only when \(2m \le 4\). Past two arguments it is a sweep of \(m(m+1)/2\) evaluations at order 2, one per pair, which is the usual shape of a forward mode.

Mixed orders

An operand of order 2 carries nothing of a third derivative, and filling it with zeros would state that the third derivative vanishes. A mixed expression therefore computes at the smallest order present, and the extra components of the others are dropped. flx::restrict_to<Ord> performs that descent explicitly, on the scalar form as on the wide one.

Only a lone scalar adapts to what it is mixed with. Everything that carries a structure states its own element type, and two operands stating different ones have no common type at all, which is a refusal rather than an arbitration.

Several points at once

A component may be a SIMD register rather than a scalar, and the construction goes through unchanged. eve::wide<flx::hyperdual<double,2>> is a structure of arrays holding as many hyperduals as the machine has lanes, and seeding a wide value seeds every lane, so one evaluation returns the derivatives at as many points as there are lanes.

This is a different axis from the order. The order says how many derivatives one point carries, the cardinal how many points travel together, and each is read where it is written: the order from the element type, the cardinal from eve::cardinal_v. Two operands that are genuinely wide have to agree on their number of lanes.
