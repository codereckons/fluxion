An evaluation on hyperduals returns all the derivatives it carries at once, and the seeding of the arguments fixes the argument each of them is taken with respect to.

Three calls seed a value:\+


\begin{DoxyItemize}
\item {\ttfamily \doxylink{group__types_gad882c0e62192532ad693d74ebdeb394d_gad882c0e62192532ad693d74ebdeb394d}{flx::\+variables}}, over the arguments of a call;
\item {\ttfamily \doxylink{group__types_ga487d2e600f4745c7eae18474d9641300_ga487d2e600f4745c7eae18474d9641300}{flx::\+variable}}, over a single value;
\item the constructor {\ttfamily hyperdual\texorpdfstring{$<$}{<}T, Ord\texorpdfstring{$>$}{>}\{v, \doxylink{group__types_ga02fcc261be278ce3a28010fe7f07b998}{flx::\+var}\}}, which builds what {\ttfamily \doxylink{group__types_ga487d2e600f4745c7eae18474d9641300_ga487d2e600f4745c7eae18474d9641300}{flx::\+variable}} returns.
\end{DoxyItemize}

No other operation seeds:\+ an operation on seeded elements propagates their units, and an element built from a tuple takes the components written in it.\hypertarget{flx_seeding_flx_assignment}{}\doxysubsubsection{\texorpdfstring{Differentiation list}{Differentiation list}}\label{flx_seeding_flx_assignment}
{\ttfamily \doxylink{group__types_gad882c0e62192532ad693d74ebdeb394d_gad882c0e62192532ad693d74ebdeb394d}{flx::\+variables}\texorpdfstring{$<$}{<}Is...\texorpdfstring{$>$}{>}(xs...)} takes the list of the differentiations requested:\+ one entry per differentiation, each naming the argument to differentiate with respect to, arguments being numbered from zero. {\ttfamily \doxylink{group__types_gad882c0e62192532ad693d74ebdeb394d_gad882c0e62192532ad693d74ebdeb394d}{flx::\+variables}\texorpdfstring{$<$}{<}0, 0, 1\texorpdfstring{$>$}{>}(x, y)} therefore requests two differentiations in {\ttfamily x} and one in {\ttfamily y}. {\ttfamily \doxylink{group__types_ga487d2e600f4745c7eae18474d9641300_ga487d2e600f4745c7eae18474d9641300}{flx::\+variable}\texorpdfstring{$<$}{<}Ord\texorpdfstring{$>$}{>}(v)} is the one-\/argument form, with {\ttfamily Ord} differentiations in {\ttfamily v}.

The list holds at most {\ttfamily \doxylink{group__traits_gaed37f490e5110e8f701e14bc2ee3f960}{flx::\+max\+\_\+order}} entries, four, and each entry names an argument of the call:\+ {\ttfamily \doxylink{group__types_gad882c0e62192532ad693d74ebdeb394d_gad882c0e62192532ad693d74ebdeb394d}{flx::\+variables}\texorpdfstring{$<$}{<}0, 0, 1\texorpdfstring{$>$}{>}(2.\+5)} names a second argument the call does not have, and does not compile.

Seeding writes that list into the values. For {\ttfamily Is...} $= (i_0, \dots, i_{n-1})$, argument $j$ of value $a_j$ is seeded as

\[ x_j = a_j + \sum_{k\,:\,i_k = j} \varepsilon_{k+1}, \]

each unit belonging to exactly one argument and every seeded result having order $n$:\+

\hypertarget{flx_seeding_flx_taylor}{}\doxysubsubsection{\texorpdfstring{Taylor identity}{Taylor identity}}\label{flx_seeding_flx_taylor}
Once the arguments are seeded, the content of each component after the evaluation follows from one identity. Substituting a nilpotent into an analytic function turns its series into a sum with finitely many terms, since every monomial of degree $n+1$ or more in the units vanishes, and that truncation is an identity rather than an approximation.

Evaluating $f$ on the arguments seeded by that list, where unit $u$ belongs to argument $i_{u-1}$, gives

\[ f(x_1,\dots,x_m) = \sum_{S \subseteq \{1,\dots,n\}}
    \left(\frac{\partial^{|S|} f}{\prod_{u \in S} \partial x_{i_{u-1}}}(a_1,\dots,a_m)\right)
    \varepsilon_S. \]

Every component of the result is a partial derivative of $f$ at the point, and it carries no factorial:\+ each unit appears to the first power, so the coefficient of $\varepsilon_S$ is the derivative itself.\hypertarget{flx_seeding_flx_landing}{}\doxysubsubsection{\texorpdfstring{Reading a result}{Reading a result}}\label{flx_seeding_flx_landing}
The Taylor identity attaches the derivative indexed by $S$ to $\varepsilon_S$, and $\varepsilon_S$ is stored at the component of index $\sum_{u \in S} 2^{u-1}$. Reading a derivative is therefore one {\ttfamily flx::\+get} at that index, and writing the index in binary shows the units it carries. Several components hold the same derivative:\+ $\varepsilon_1\varepsilon_3$ and $\varepsilon_2\varepsilon_3$ both hold $\partial^2 f/\partial x\,\partial y$.\hypertarget{flx_seeding_flx_cost}{}\doxysubsubsection{\texorpdfstring{Cost of an order}{Cost of an order}}\label{flx_seeding_flx_cost}
An element of order $n$ has $2^n$ components, so a single element of order 4 occupies sixteen {\ttfamily double}s, and every operation of the arithmetic works on all of them. An order is used in one of two ways.


\begin{DoxyItemize}
\item {\bfseries{One unit per argument.}} Order $m$ over $m$ arguments returns the gradient and every mixed partial up to the one of order $m$, in one evaluation, and no repeated derivative.
\item {\bfseries{Several units per argument.}} Order $n$ over one argument returns $f\textnormal{\textquotesingle}, f\textnormal{\textquotesingle}\textnormal{\textquotesingle}, \dots, f^{(n)}$ of that argument in one evaluation, and no derivative in the others.
\end{DoxyItemize}

A full Hessian in $m$ arguments therefore takes a single pass only when $2m \le 4$. Past two arguments it takes a sweep of one of two kinds:\+


\begin{DoxyItemize}
\item at order 2, one evaluation per pair, $m(m+1)/2$ of them, the pairs $(i, i)$ giving the square terms;
\item at order 4, two units on each argument of a pair, $m(m-1)/2$ evaluations, each returning both square terms and the mixed one.
\end{DoxyItemize}\hypertarget{flx_seeding_flx_mixing}{}\doxysubsubsection{\texorpdfstring{Mixed orders}{Mixed orders}}\label{flx_seeding_flx_mixing}
An operand of order 2 carries no third derivative, and filling it with zeros would state that the third derivative vanishes. A mixed expression therefore computes at the {\bfseries{smallest}} order present, and the extra components of the others are dropped. {\ttfamily flx::\+restrict\+\_\+to\texorpdfstring{$<$}{<}Ord\texorpdfstring{$>$}{>}} performs that reduction explicitly, on the scalar form and on the wide one alike.

Only a plain scalar converts to the type it is mixed with. A hyperdual or a wide fixes its element type, and two operands with different element types have no common type:\+ mixing them does not compile.\hypertarget{flx_seeding_flx_wide}{}\doxysubsubsection{\texorpdfstring{Evaluation on SIMD registers}{Evaluation on SIMD registers}}\label{flx_seeding_flx_wide}
A component may be a SIMD register rather than a scalar, and the construction is unchanged. {\ttfamily eve::\+wide\texorpdfstring{$<$}{<}\doxylink{structflx_1_1hyperdual}{flx::\+hyperdual}\texorpdfstring{$<$}{<}double,2\texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}} is a structure of arrays holding as many hyperduals as the machine has lanes, and seeding a wide value seeds every lane, so one evaluation returns the derivatives at as many points as there are lanes.

The cardinal is independent of the order:\+ the order counts the derivatives carried at one point, the cardinal the points evaluated together. The order is read from the element type, the cardinal from {\ttfamily eve::\+cardinal\+\_\+v}, and two wide operands must have the same number of lanes.
