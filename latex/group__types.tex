{\ttfamily \+\#include $<$fluxion/\+types/\+variables.\+hpp$>$}



Turn a value into a variable of the given order. 

The value goes in the constant slot and a one in front of each of the {\ttfamily Ord} nilpotent units, so that every derivative up to {\ttfamily Ord} flows from it. It is {\ttfamily \doxylink{structflx_1_1hyperdual}{hyperdual}\texorpdfstring{$<$}{<}T, Ord\texorpdfstring{$>$}{>}\{v, \doxylink{structflx_1_1as__var}{as\+\_\+var}\{\}\}} with the type worked out rather than spelled, an order never being deducible from a value alone.

{\ttfamily \+\#include $<$fluxion/\+types/\+variables.\+hpp$>$}



Turn the arguments of a call into variables, each along the units it is differentiated by. 

{\ttfamily Is...} is the list of derivations asked for, one entry per nilpotent unit:\+ entry {\ttfamily u} names the argument that unit {\ttfamily u} belongs to. Its length is therefore the order, {\ttfamily \doxylink{group__types_gad882c0e62192532ad693d74ebdeb394d_gad882c0e62192532ad693d74ebdeb394d}{variables}\texorpdfstring{$<$}{<}0, 0, 1\texorpdfstring{$>$}{>}(x, y, z)} asking for two derivations in {\ttfamily x}, one in {\ttfamily y}, and none in {\ttfamily z}.

Every argument named at least once comes back as a hyperdual seeded on its own units, every other one comes back untouched, at its own type, so the result feeds a call straight through {\ttfamily kumi::\+apply}.
