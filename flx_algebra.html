Hyperdual Algebra

Obtaining a Derivative ends on forward mode, which needs a place to keep a value together with the derivatives asked of it, and an arithmetic that updates both at every operation. A number carrying its own derivative is that place.

Clifford's dual numbers, of 1873, carry one derivative. Fike and Alonso added a second unit in 2011 and named the result a hyper-dual number, the prefix marking the several units as it does for the hypercomplex numbers built on more than one imaginary unit. FLUXION takes \(n\) units rather than two, which is what generalized names here. They form an algebra, and each of its properties has a name in the library.

One unit

Adjoin to the reals a symbol \(\varepsilon\) with \(\varepsilon \neq 0\) and \(\varepsilon^2 = 0\). An element is a pair \(a + b\varepsilon\), and products close on that form, since the \(\varepsilon^2\) term vanishes:

\[ (a + b\varepsilon)(c + d\varepsilon) = ac + (ad + bc)\,\varepsilon. \]

The coefficient of \(\varepsilon\) obeys the product rule of Rules of computation, and for a function built from the arithmetic operations and the usual elementary functions,

\[ f(a + \varepsilon) = f(a) + f'(a)\,\varepsilon. \]

This is the complex step made algebraic, with \(\varepsilon^2 = 0\) in place of \(i^2 = -1\). No \(h\) has to be chosen and nothing cancels, and the coefficient of \(\varepsilon\) is the derivative to the last bit the representation holds. In the library such a number is a type carrying its order:

flx::hyperdual<double,1> z{2.5, 1.0}; // 2.5 + e1

Several units

A second unit brings \(\varepsilon_2\), and with it the product \(\varepsilon_1\varepsilon_2\), which does not vanish since the two units are distinct. That component is where the second derivative lands. Let \(\varepsilon_1, \dots, \varepsilon_n\) commute with each other and with the reals, and let each square to zero. The algebra they generate is

\[ \mathcal{H}_n = \mathbb{R}[\varepsilon_1,\dots,\varepsilon_n] \big/ \left(\varepsilon_i\varepsilon_j - \varepsilon_j\varepsilon_i,\ \varepsilon_i^2\right), \]

a Weil algebra, the \(n\)-fold tensor power of \(\mathbb{R}[\varepsilon]/(\varepsilon^2)\). A product of distinct units is not zero, and any product in which a unit appears twice is. The surviving products are therefore indexed by the subsets of \(\{1,\dots,n\}\). Writing \(\varepsilon_S = \prod_{i \in S} \varepsilon_i\), the basis is \((\varepsilon_S)_{S \subseteq \{1,\dots,n\}}\), the dimension is \(2^n\), and the product of two basis elements is

\[ \varepsilon_S\,\varepsilon_T = \begin{cases} \varepsilon_{S \cup T} & \text{if } S \cap T = \emptyset, \\ 0 & \text{otherwise.} \end{cases} \]

FLUXION calls \(n\) the order and carries it in the type. The order is bounded, each one doubling the number of components stored:

flx::hyperdual<double,1> a; // 2 components: 1, e1
flx::hyperdual<double,2> b; // 4 components: 1, e1, e2, e12
flx::hyperdual<double,3> c; // 8 components: the subsets of three units
flx::hyperdual<double,4> d; // 16 components: the subsets of four units
flx::order_v<decltype(c)>; // 3
flx::dimension_v<decltype(c)>; // 8
flx::max_order; // 4

Four is where FLUXION stops. A value of order 4 holds sixteen components, every operation of the arithmetic works on all of them, and several of them answer the same derivative (see Reading a result).

Component indexing

An element carries one coefficient per subset of the units, and is the sum of them:

\[ z = \sum_{S \subseteq \{1,\dots,n\}} z_S\,\varepsilon_S = z_\emptyset + z_{\{1\}}\varepsilon_1 + \dots + z_{\{1,\dots,n\}}\varepsilon_1\cdots \varepsilon_n. \]

The empty subset multiplies no unit, so \(z_\emptyset\) is the ordinary number the element is built around, and FLUXION calls it the value. The other \(2^n - 1\) coefficients form the nilpotent part.

Each coefficient is a component of the stored value, and its index says which units it belongs to, one bit per unit: bit \(i\) set means the component carries \(\varepsilon_{i+1}\). Index zero holds the value, and the indices that are powers of two hold the coefficients of the single units.

flx::get<0>(z); // the value
flx::get<1>(z); // the coefficient of e1
flx::get<3>(z); // the coefficient of e1 e2, bits 0 and 1 both set

Streaming a value prints the same names, the value unnamed and the others suffixed:

std::cout << flx::hyperdual<double,2>{1.0, 2.0, 3.0, 4.0}; // 1 + 2e1 + 3e2 + 4e12

Constants and variables

A value carrying no nilpotent part is a constant: differentiating anything against it returns zero. A value carrying a one in front of every unit is a variable, which is what makes derivatives flow from it.

flx::hyperdual<double,2> k{2.5}; // 2.5, a constant
flx::hyperdual<double,2> x{2.5, flx::var}; // 2.5 + e1 + e2, a variable

A hyperdual is filled exactly. The three forms above and a tuple of the exact size are the only ways to build one, a partial list being refused rather than completed:

flx::hyperdual<double,2> z{1.0, 2.0, 3.0, 4.0}; // four values for four components
flx::hyperdual<double,2> w{1.0, 2.0}; // refused at compile time
Note
Completing by zeros would state that the missing derivatives vanish, which is an assertion about the function rather than a convention about storage.

Sum, product, and inverse

\(\mathcal{H}_n\) is commutative and associative at every order, so an expression means what it is written to mean at order 4 as much as at order 1, and no parenthesis has to be watched. What grows is the size, doubling with each order, and every operation works on all of the components.

It is not a division algebra. Every element whose value is zero is nilpotent, hence a zero divisor. An element is invertible exactly when its value is, and the inverse is then a finite sum, the nilpotent part \(N\) satisfying \(N^{n+1} = 0\):

\[ \frac{1}{a + N} = \frac{1}{a}\sum_{k=0}^{n} \left(\frac{-N}{a}\right)^{k}. \]

Every arithmetic operator and every elementary function applies to a hyperdual and returns one, its components being those the algebra prescribes:

auto s = x + y; // added component by component
auto p = x * y; // the product above, unit by unit
auto q = x / y; // defined exactly when the value of y is
auto e = flx::exp(x); // the value, and every derivative it carries

No order relation

An ordered ring has no nilpotent element other than zero: were \(\varepsilon > 0\), squaring would give \(0 > 0\). No comparison of two hyperduals can therefore extend the comparison of the reals, and the library compares values:

x == y; // compares the values alone
x < y; // absent

Reading a derivative is done by component, by name or by index, and never by comparison.

Lower orders as prefixes

The units \(\varepsilon_1, \dots, \varepsilon_k\) generate a subalgebra of \(\mathcal{H}_n\) for \(k \le n\). The binary layout of the indices places it first: the first \(2^k\) components are exactly the subsets of the first \(k\) units, so reading an order \(k\) out of an order \(n\) is taking a prefix, component for component.

flx::hyperdual<double,4> z;
auto y = flx::restrict_to<2>(z); // the first four components, unchanged

The extraction is exact, and there is nothing that goes the other way: raising an order would fill components with zeros the operand never held.
